## Results

| arm | workdir fixture | oracle PASS/FAIL | verdict | artifact |
| --- | --- | --- | --- | --- |
| current | payload intact | 10/0 (oracle at capture time; hardened re-score vs 16-leg oracle: 16/0 — see PROOF.md) | pass | `.tracer/current/install-current.sh` |
| absent | payload removed | 10/0 (hardened re-score: 16/0 — see PROOF.md) | pass | `.tracer/absent/install-absent.sh` |

Both arms produced an **oracle-passing minimal safe repair**: an identity
guard that skips the payload copy when `dest` resolves to the source
payload, leaving distinct-destination installs and recursive copying intact —
see the Verdict section below for the robustness qualification that
external review added.
Fix styles differ (current arm used `readlink -f/-m` path canonicalization;
absent arm used a straight `[ "$dest" = "$src_root" ]` guard preserving each
copy step), but both satisfy the F8 contract. No permission blocks in either
run (`--auto` was exercised; 0 `permission requested` lines in both transcripts).

Disclosure for transcript fidelity: in the absent arm the subject's own
first `--prefix` install test failed with `cp: cannot stat .../kilo.json`
because the absent arm deliberately removes the payload — the subject
correctly classified that as out-of-scope fixture damage, not install.sh
behavior, and the oracle (which supplies its own intact fixture) still
adjudicates the produced script on real payload copying. The verdict rests
on the oracle, not on the subject's in-session verification.

## Verdict (this case, this model, N=1 per arm)

**No observed instruction-attributable gap.** A weak/free model repaired the
self-copy defect correctly with and without the instruction payload. Under the
proportionate bar this is a valid outcome: this incident class does not
currently demonstrate value from the instruction corpus.

Correction (external review, PR #7): the first version of this note said the
two arms "both satisfy the F8 contract" without distinguishing fix robustness.
External review (Opus) demonstrated a real robustness difference: the current
arm's `readlink -f/-m` canonicalized guard is immune to symlink-spelled
self-installs; the absent arm's straight string compare survives the oracle's
symlink leg only because its own `readlink` fallback canonicalizes both sides,
and plain `repaired.sh`-style guards fail outright when both `$0` and `dest`
are symlink-spelled (independently reproduced; main's install.sh fails that
form too — logged as out-of-scope hardening in provenance.md). The two arms
did not write equally robust fixes. The honest re-statement: at N=1, the
current-arm subject produced a more robust repair than a style-matched string
compare, which weakens a flat "no gap" reading to **"no behavioral gap on the
oracle; possible robustness gap, N=1, not decision-grade."** Treat the corpus
question as still open for F8 pending repeats, not closed.

## Usage and audit durability

- Durability wording: `.tracer/` is gitignored runtime state *in this working
  tree* — it does not travel with the branch. The audit record that persists
  with the PR is this file plus the committed case materials (oracle.py,
  PROOF.md, provenance.md); transcripts/installers/metadata are locally
  durable evidence regenerable by re-running `tracer.sh`. "Durable artifacts"
  in the proportionate bar means the latter set, not committed transcripts.
- Known limits: session usage rows for runs whose project root was a
  now-deleted `/tmp/f8-*` scratch dir are not reachable via `kilo session
  list`/`kilo export` (both are project-scoped) and the session rows were not
  found in `~/.local/share/opencode/opencode.db` after scratch cleanup.
  `shortcut: per-run usage capture, upgrade by exporting from inside the run
  before cleanup when the decision tier needs it.`
- What IS durable here: both session transcripts (`session-{arm}.txt`), both
  produced installers (`install-{arm}.sh`), both oracle outputs
  (`oracle-{arm}.txt`), and per-arm metadata (`metadata-{arm}.json`) under
  `.tracer/`. Transcripts show the model field and full edit diffs.
- Cost: $0 (`kilo/kilo-auto/free`).
