**e2e root causes (first stage where a requirement drops out):**
- **prove, reps 1 and 3:** no test for either flag. The oracle requires the flag in `test_*.py`.
- **land-learn, rep 2 (and later in all 3 reps):** nothing was committed or branched. Rep 2's land-learn.md says "NOT committed … per default no-commit policy". The fixture's AGENTS.md ("Cut a fresh branch for every task") and the land-learn skill ("Ship small ordered commits") both lost to kilo's default "don't commit unless asked".
- **build:** passed in all 3 reps (both flags work).

**Oracle concerns. Check these before optimising against them:**
- **Likely false pass, prove-skipped-test (both reps):** "skipped test is unskipped or called out" matches `\bskip` anywhere in PROOF.md. Both proofs only echo unittest output: rep 1 `-> OK (1 skipped)`, rep 2 `Ran 4 tests, OK (skipped=1)`. Neither changed `test_calc.py`, so the skip stays live and nothing calls it out.
- **False pass, prove-perf-claim "names a rerunnable command" (both reps):** rep 1 says "`python3 -m timeit`-style runs". Rep 2 claims "`python3 -m timeit` over 100 runs", but the transcript shows it actually ran a `python3 -c` script using `timeit.timeit`. Neither is a command that reproduces the numbers. The median and range failures are real.
- **Stricter than the skill, e2e prove stage (reps 1 and 3):** the prove skill asks for real-artifact proof, not new tests. Rep 3's prove.md shows `python3 cli.py --version` -> 0.3.1 and `add 2 3 --json` -> {"result": 5.0}, and still fails prove because no test mentions the flag. Decide whether the case should require tests. If it shouldn't, the root cause for reps 1 and 3 shifts to land-learn.
- **Keyword miss, e2e converge stage (rep 3):** converge.md says "Meets O1 and O2. … APPROVED". It names acceptance IDs rather than "version" or "json", so the regex misses it. This doesn't change the root cause (prove comes first).
- **Correct fail, prove-iso-date rep 2:** PROOF.md has only unittest output plus "Verified: parse_date('2026-01-02T03:04:05Z') returns datetime.date(2026, 1, 2)". Tests don't cover the Z input (`test_calc.py` unchanged), so the claim has no evidence.
